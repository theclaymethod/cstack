# Expert-review eval evidence ledger

## Contract frozen before the adversarial round

Intended capability: faithfully preserve expert judgments, corrections, uncertainty, scoped binary criteria, provenance, and original reviewed versions as reusable local eval data. Expert-mode captures in the same turn only while active. Distill-me extracts retrospectively, merges prior capture without duplication, preserves amendments/retractions, and leaves ongoing capture state unchanged. Short, useful replies and selective clarification support the expert's work. Agent suggestions, successful edits, silence, archived directives, and summary-only claims do not become confirmed expert labels.

Permitted alternatives: incomplete negative annotations without a supplied correction; provisional summary observations with explicit gaps; faithful binary paraphrases; reporting no supported judgments when appropriate. Replay readiness requires sufficient source context and a supported observable criterion. No clinical truth or probability-calibration claim is in scope.

Runtime: local JSONL/Markdown plus Python standard library. No SQLite is needed; there is no relational workload. No Docker is needed for this data-only grader: it never executes submitted code. Candidate file access is an instruction boundary on the host, not an OS sandbox. Permission enforcement, secret resistance, and hostile executable containment are unverified. Operator receipts are in a separate sibling tree and are never candidate evidence.

Candidate access: the revealed workspace REQUEST.md, CURRENT_TURN.md, cumulative source.json, supplied artifacts, and existing dataset. Writes: only dataset/reviews.jsonl, dataset/rubric.jsonl, reply.md. No grader, reference answers, future events, operator state/receipts, network, or background processes. Reviewers have white-box source access to form hypotheses; valid counterexamples must use only candidate-permitted data writes and the trusted operator prepare/capture/grade API. Changes to protected state are out of scope.

Scoring entrypoint: `python3 evals/expert-review/run.py grade OPERATOR`. All structural checks must pass for artifact credit. `skill_evaluation_complete` stays false: semantic correctness, useful clarification, reply quality, and real review/source-access behavior require review of actual artifacts and execution. A handwritten baseline does not measure an agent's skill.

Frozen revision: fixture v1, grader v1. The initial six-case reference baseline and five insufficient-output controls passed 11/11 calibration checks in `eval-runs/expert-review-initial/summary.json`. Files and target skill snapshots were frozen with SHA-256 hashes in `eval-runs/expert-review-v1/manifest.json`. These are development/calibration runs, not held-out results.

Attack budget: one independent round, three lanes (verifier, lifecycle/environment, task contract), maximum two concrete attempts each, with isolated lane directories under `eval-runs/expert-review-v1/`. Coordinator owns repairs. Clean replays and repair validation do not start a second discovery round.

## Round and repair receipts

The verifier and task-contract lanes each completed two attempts against the frozen v1 grader. The lifecycle lane was blocked by an automated cybersecurity-risk review before producing a result; it was not retried. The three-lane dispatch therefore does not establish completed environment coverage. White-box review supplied hypotheses; all four accepted findings used only candidate-permitted dataset/reply writes and the actual operator grading path. The coordinator cleanly replayed each original submission before and after repair. No candidate executable was run.

Evidence: `evidence/round-1/submissions.json` retains data at every checkpoint. `before-after.json` and the per-submission original/repaired grade JSONs record the observed outcomes. `frozen/` preserves the original verifier, fixtures, candidate contract, and calibration. Reviewer reports distinguish proxy credit from full skill success. Reproduce with the two `replay.py` commands in README.

Additional construction improvements: v2 copies versioned target guidance into each workspace; hashes request/guidance/grader/fixtures in operator metadata; bounds regular-file reads before copying; reveals regenerated assets only at the relevant turn; and applies inactive-state preservation to both review and rubric files. These narrow the original design assumptions. They are not counted as findings or completed adversarial lifecycle coverage. The reference suite passes; hostile host-permission enforcement remains unverified.

Validation: fixture v2 / grader v2 passes all 15 calibration controls: six original references, five original insufficient outputs, two new invalid submissions, and two valid alternatives. Four preserved real reviewer submissions reverse their v1 outcomes as intended. All are development evidence, with no held-out or causal improvement claim.

Reusable guidance was persisted in `skills/cross-examine/references/lessons.md` and the installed copy: preservation starts with supplied history; required identity/version fields need validation; example lineage and amendment provenance are distinct; allowed incomplete states require positive calibration. These lessons cite the preserved round receipts. Target skill semantics were not weakened to fit the grader.

## Skill pilot and intent verdict

Six fresh-agent cases ran against frozen v2 with operator-captured checkpoints: five artifact passes, one uncertainty-case failure. Actual records/replies and original grades are preserved in `evidence/pilot-v2/pilot.json`; frozen source/guidance and hashes are alongside. The failure was not erased: current-grader replay still rejects that original output.

Read-only independent adjudication of the pilot distinguished an actual missing proposed criterion from adapter defects and ambiguity. V2 required a yes/no passing answer despite permitting uncertainty; a legitimate proposed criterion with a null passing answer fails v2 and passes v3. The rubric's later confirming expert statement is legitimate provenance, so the original-source restriction was broadened. The example unit was previously ambiguous; v3 explicitly declares one assertion per example before requiring two active chains. The earlier count failure is not labeled a demonstrated pure grading defect or fabricated numerical error. Adjudication and the legitimate alternative are in `evidence/pending-rubric-v3/`.

The shared record guidance was clarified to persist a proposed criterion before asking. A fresh v3 development candidate saved it, retained the separate numeric concern, and appended the confirmed rubric version. Its original grader nevertheless rejected the source-error example for lacking a replacement probability. Independent adjudication confirmed a false rejection: a supported source-naming criterion is sufficient for that scoped error, while numerical uncertainty remains separate. Fixture v3 / grader v4 removes the irrelevant blocker. Replaying the unchanged v3 candidate now passes. The original rejection, current acceptance, and full output remain in `evidence/pilot-v3/` and `evidence/final-validation/readiness-before-after.json`. No fresh v4 model run or causal advantage is claimed.

Final validation: 19/19 current calibration controls pass. The original four round submissions retain the correct repaired outcomes; the pending criterion and criterion-only negative examples pass, while malformed confirmed/pending criteria fail. Final receipts and source/guidance hashes are in `evidence/final-validation/`. New confirmed mechanisms were also taught in Cross-Examine's existing lessons reference. The core skill's ability to use a rubric without a complete replacement was preserved rather than weakened.

Intent verdict: this suite now measures a narrower defensible artifact proxy for faithful expert capture. Source-verified record/reply inspection supports the five passing v2 scenarios and the focused v3 scenario described in REPORT.md. Clinical truth, real product/graph coverage, cross-application behavior, restart/compaction, write-failure recovery, concurrent writers, and enforced source-access restrictions remain unverified. The blocked lifecycle lane is incomplete. Every machine result retains skill_evaluation_complete false; calibration and data replay are never presented as proof of full skill success. Independent extraction panels were not exercised in these short-session candidates. All runs were development evidence; no held-out reliability or causal learning claim is made.
