# Co-climb revision validation

Validated 2026-11-13 against baseline `03eeb4bc95ad89d805b008a8165a89cceafc9cc1`.

## Changes

The original skill described alternating blocks but did not define a bounded branch archive or explicit coordinator/target/judge handoff prompts. Its entrypoint also treated predominantly clean in-loop judgments as proof of final-judgment noise, while its protocol correctly required identity checks and repeated measurements first.

The revision adds evidence-backed branching, parentage, archive caps, and distinct exploratory versus promoted states. A specialist may remain worth exploring without satisfying the two-set promotion gate. A judge change invalidates rankings and triggers regrading before selection. Judge candidates are selected for label agreement and costly errors, not generous product scores. The entrypoint now preserves the protocol's cautious disagreement diagnosis and fresh-execution requirement for in-loop changes.

The new prompts specify frozen identities, mutable boundaries, evidence, budget and returned artifacts for each role. They are instructions, not a bundled runtime or automatic permission to launch workers. The installed skill still contains only Markdown and project-local handoffs.

## Executed checks

- Nine grader tests passed, including the real CLI and input preparation.
- All 16 synthetic reference decisions passed. A legitimate archive alternative and reordering of independent actions also passed.
- All 33 offered unsafe-action additions and all 35 required-action omissions were rejected.
- Controls reject greedy branch collapse, premature promotion, reversed evidence dependencies, malformed/duplicate answers and partial coverage. Missing cases remain in the denominator.
- The existing playground suite ran 56 tests successfully with one skipped.
- Skill frontmatter validation and relative-link checks passed.

[Validation counts and source hashes](evidence/validation.json), [grader control output](evidence/grader-controls.txt), and [playground output](evidence/playground-controls.txt) preserve the observations. The validator initially lacked PyYAML; it passed using an isolated `uv run --with pyyaml` environment. No dependency was added to the installed skill.

## Limits

These are synthetic, authored decision scenarios and grader controls. Reference answers were authored from the contract, not generated by an agent or supplied as human gold. The suite does not prove native campaign execution, model calibration, search efficiency, receipt integrity, or prompt effectiveness. There were zero model/provider calls. No live before/after comparison was run, so no measured skill-quality gain is claimed.

All cases are exposed development evidence. The runner prepares answer-free prompts and records source hashes for a future frozen-runtime comparison. A separate fresh-family execution suite is needed for end-to-end and generalization claims. The original sealed-set, authority, noise and confirmation requirements remain in force.
