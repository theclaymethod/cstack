# Reward-hacking and evaluation-design ledger

This is the project ledger for `$cross-examine`. It records mechanisms and bounded prevention evidence, including failures in the outer eval. Historical results stay attached to the version that produced them. General generation rules live in the [skill's lessons](../../skills/cross-examine/references/lessons.md).

## 2026-11-06: intended outcome and evidence boundary

The eval should measure whether an agent independently finds and reproduces a real eval defect, repairs its cause while preserving valid outcomes, and teaches a generator a supported lesson. The outer grader must not perform the candidate's discovery for it. Efficient legitimate solutions are valid; a surprising finding in a control deserves adjudication.

Artifact replay establishes narrower facts than discovery, swarm use, or lesson quality. The historical pilot was used to improve the grader and is development evidence. The address-update to order-cancellation exercise is near transfer within SQLite. Held-out reliability, broad generalization, and causal learning improvement remain unmeasured.

Original public version: commit `41a14e4eedf6c3fcf52837c68907dd28c2b581a1`, fixture version 2, before an explicit grader version existed. This review introduces grader version 3 without rewriting prior results.

## 2026-11-06: intent-review outcome and remaining gaps

The original executable proxy conflicted with the intent in two reproduced ways: it accepted missing candidate reproduction and missing teaching work. The [frozen incomplete submission](evidence/intent-review-2026-11-06/missing-discovery-and-lesson/submission/) remains available for replay. Version 3 closes those structural gaps and marks the full skill evaluation incomplete pending review. The [version 3 calibration](evidence/intent-review-2026-11-06/calibration-v3/summary.json) records positive references, insufficient repairs, missing deliverables, and adjudication routing separately.

The two model pilots remain development results, not held-out scores. The grader changed after seeing output, discovery agents had instruction-only host access limits, and the transfer exercise has no original-guidance baseline. The original and transferred guidance are byte-identical (SHA256 `c18ec7f011dde64aa00f6f5c816f29420d5fc7df9bf7795ef3fdc0c5988e903f`), but this retrospective comparison is not an independently protected pre-run receipt.

For future scored runs, freeze grader/request/guidance hashes before candidates run, retain receipts outside candidate access, enforce the discovery boundary, use fresh held-out variants, and review actual discovery, swarm behavior, and lessons. Published cases and their solutions are development materials. Until those conditions are met, no complete skill-success or broad-generalization claim is supported.

Append later observations and replays here; preserve this account if a prevention regresses or a new defect invalidates a control.


## 2026-11-06: minimal-tooling execution

The skill now defaults to ordinary local files for task state, lessons, and the ledger. SQLite is conditional on database semantics; the existing database examples retain it because SQL updates and reset behavior are their explicit contract. Docker is optional and reserved for isolation that the host runner cannot enforce. No database service or third-party Python package is required.

Grader version 4 adds local execution as the default, explicit `--executor local|docker` selection, and an `execution_boundary` in results. Fixture version 3 makes the access-trap oracle path portable. The local oracle path is ordinary host storage, not protected evaluator state. Local mode can establish artifact behavior for trusted/reviewed programs but cannot substantiate permission-dependent prevention claims. In particular, the earlier read-only mount evidence applies to Docker, not local execution. No automatic Docker-to-local fallback exists.

Both the [local calibration](evidence/minimal-tooling-2026-11-06/local-summary.json) and [Docker calibration](evidence/minimal-tooling-2026-11-06/docker-summary.json) passed all 11 checks. Local calibration ran with `PATH=/nonexistent`, so Docker was unavailable on its command path. The existing timeout probe [returned code 124](evidence/minimal-tooling-2026-11-06/local-timeout.json) and left no live processes in its ordinary POSIX process group. This is timeout hygiene, not containment of programs that deliberately escape a process group. The [receipt](evidence/minimal-tooling-2026-11-06/receipt.json) records versions and retrospective source hashes.

Intent verdict: these development calibrations preserve the narrower artifact checks and negative controls. They do not establish discovery, swarm behavior, useful teaching, held-out reliability, or local isolation. The runner continues to mark the full skill evaluation incomplete. Scored audits must declare their executor and enforce any permissions on which their conclusions depend.


## 2026-11-06: structural infrastructure safeguards

Grader version 5 implements backlog issues [1](https://github.com/theclaymethod/cross-examine/issues/1), [2](https://github.com/theclaymethod/cross-examine/issues/2), and [3](https://github.com/theclaymethod/cross-examine/issues/3). The intended distinction is candidate failure versus an environment that cannot run or terminate the replay reliably. These safeguards add no tooling to local execution.

- **Mount access:** Docker grading and transfer preflight a host/container file round trip in fresh scratch under the configured root. `WARGAMES_SCRATCH_ROOT` (renamed to `CROSS_EXAMINE_SCRATCH_ROOT` later) selects an explicitly shared writable location; the existing workspace-local default remains. External submissions are staged under the same root. The [default-root preflight](evidence/structural-improvements-2026-11-06/preflight.json) and an [explicitly configured shared root](evidence/structural-improvements-2026-11-06/shared-scratch-preflight.json) passed. The [system temporary root check](evidence/structural-improvements-2026-11-06/storage-checks.json) reproduced a mount failure on this context and returned an unscored infrastructure error before submitted code ran. An invalid scratch root also returned an actionable error.
- **SQLite lifecycle:** The same preflight seeds trusted rows, compares container and host reads, rewrites the existing file with different rows, repeats both reads, runs the trusted reconstructing reset, and confirms both readers see initial state. It retains stable host seeding and fresh per-probe directories. These checks passed across the actual Docker boundary; they are bounded environment health evidence, not proof against all mount or SQLite failures.
- **Container cleanup:** Each replay records removal and an exact-name query, distinguishing absent, present, and unknown. A removal failure or uncertain daemon response cannot silently imply termination. The existing parent/child [timeout probe](evidence/structural-improvements-2026-11-06/runtime-checks.json) timed out with the exact container confirmed absent; normal auto-removal also passed. An unreachable daemon produced unknown cleanup and an unscored infrastructure error. An [injected removal refusal](evidence/structural-improvements-2026-11-06/cleanup-failure.json) left a real timed-out container present, raised the infrastructure error, and was followed by explicit removal and verified absence. The refusal was a controlled fault injection, not a naturally observed daemon failure.

Both [local](evidence/structural-improvements-2026-11-06/local-summary.json) and [Docker](evidence/structural-improvements-2026-11-06/docker-summary.json) calibration passed all 11 cases, preserving legitimate artifacts and rejection of insufficient submissions. A local CLI grade with Docker unavailable on `PATH` also passed and skipped Docker preflight. No new test files were added; verification used existing calibration/probes and direct runtime checks. The [receipt](evidence/structural-improvements-2026-11-06/receipt.json) records retrospective source hashes and limitations.

Intent verdict: infrastructure uncertainty now aborts these paths without a candidate score, while artifact checks continue to measure the same limited outcomes. Startup health does not guarantee later infrastructure health, local mode does not enforce permissions, and discovery, swarm behavior, lesson quality, and held-out reliability still require separate evidence. Full skill evaluation remains incomplete.


## 2026-11-06: current-skill execution against frozen grader version 5

The [new run report](evidence/current-skill-v5-2026-11-06/REPORT.md) records 11/11 local and 11/11 Docker calibration checks, one completed task-contract audit lane across five cases, coordinator-authored repairs/lessons passing all five artifact graders, and a fresh-agent near-transfer comparison. The original and revised generator guidance both produced passing transfer evaluations; no advantage was observed in this single pair. Input hashes were recorded before dispatch and remained equal after grading.

The intended three-lane round did not complete: verifier and environment agent calls were blocked by an automated cybersecurity-risk check, with no retries or replacement lanes. Their absence remains a coverage gap. The completed lane reproduced the three known seeded mechanisms and found no defect in its two control probes per case. These are public development cases; the parent coordinator knew their history and authored the repairs and lessons, so the artifact result is not an independent end-to-end skill success. Discovery access and provenance restrictions were instruction-only, while submitted code ran through Docker.

No new mechanism was promoted to canonical guidance. Confirmed lessons were added to the run's submitted generator artifacts; existing canonical lessons already cover them. Intent verdict: artifact behavior remains supported, full swarm behavior and independent skill effectiveness remain unestablished, and this transfer pair provides no learning-improvement evidence. See the [machine-readable summary](evidence/current-skill-v5-2026-11-06/summary.json) for counts and limitations.
