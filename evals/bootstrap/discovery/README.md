# Discovering the Undo boundary

Start with an empty SCENARIOS.md and a README containing only the opening facts. Give the interviewer its skill and the opening request. Keep the operator policy outside its workspace. Use the same thread for all replies and save the final index and dialogue. Compare fresh sessions; accept semantically equivalent questions and indexes.

Opening: “Undo should work on our shared whiteboard. When I draw a line and immediately undo, it disappears. Help me figure out what else we need to specify. Keep SCENARIOS.md as we go.”

The operator answers only the question actually asked. If asked whose history applies, say “My undo applies to my marks only.” A question about changes to the same mark, or an open invitation to describe a concrete incident that worried the owner, unlocks the hidden requirement: “If someone else has since edited my line, leave that line exactly as they edited it. Returning after I leave the board is a different issue; I haven't decided it.” If asked about persistence first, say it is undecided. For unrelated questions say there is no decision yet. Do not volunteer the hidden example for a generic request to list requirements. After disclosure, ask the interviewer to wrap up the current index; explicitly settle ownership if it was not already asked. Cap discovery at four questions/rounds; at the cap ask for the current index without supplying any missed rule.

Grade the saved index and dialogue on four independent behaviors: elicited the hidden concern before disclosure, preserved the untouched ordinary case, recorded preservation of the collaborator-edited mark, and kept rejoin unresolved if raised. Reject invented settled requirements. Count distinct settled questions the developer had to answer again, and separately report the number of interview turns to discovery. A proposal awaiting approval is permissible. Judge semantics, not IDs, labels or number of rows. An index that guesses the hidden rule as settled before eliciting it fails discovery even if the guess matches.

The [paired discovery eval](../../spec-discovery/README.md) checks whether the same question separates two possible owner policies, and whether the interview stops when the evidence already settles the rule.
