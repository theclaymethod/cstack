# Current-model prompt simplification

User authorization: use the current model only, simplify C Stack skills further, and validate through the playground fixture. No model override, provider-client calls, paid campaigns, deployment or push is authorized by this experiment.

Baseline: clean commit `3b2c7d25fff3c410b937f00bb0bcd2e6c393c2c8`, version 0.9.1, 8,722 entrypoint words. Preserve original skill frontmatter and all supporting references/scripts/assets. Only `SKILL.md` bodies may be rewritten. Unlike the preceding ablation's literal deletions, this is an explicit outcome-contract rewrite that removes procedural steering while retaining task meaning and linked operational detail.

Hypotheses: the current host model can choose routine implementation steps from concise contracts; case/source authority, amendment history, input fidelity, isolation/exposure limits, valid alternatives, budget accounting, exact final configuration and actual execution requirements remain necessary. Historical audit-derived constraints stay explicit or behind mandatory reference pointers. No claim that any deleted instruction was added specifically for an older model without source evidence.

Comparison: same current inherited host model and tools for full and simplified guidance. Only C/D-style same-model prompt comparisons are available. Older/newer-model cells, capability-upgrade effects and causal model-by-prompt interactions remain unrun. Exact hosted model snapshot unavailable. Programmed old/new fixture models test workflow mechanics only.

Objective: reduce entrypoint UTF-8 bytes and words while preserving every baseline-passing observed quality check and important behavior. Zero observed task-quality loss; no invented population loss margin or release threshold. Fixed native evaluator, cases, expectations, runtime, supporting resources and exposure rules. Semantic grades are coordinator review against a frozen checklist; independent fresh contexts execute the tasks, but this is not a blinded human study.

Budget: one combined rewrite candidate, with at most one targeted restoration if a concrete failure warrants it. Three fresh baseline and three fresh candidate agents execute matched capture/author/operations packets; two further fresh contexts perform combined confirmation. At most two additional fresh contexts may investigate a demonstrated omission. Capture/author <=48 native cases each; operations <=300 native cases plus documented offline judge workers; confirmation <=120 native cases each. No nested delegation in those exercises; limitations must be reported. Control-suite runs are separate verification counters.

Run baseline guidance before candidate evaluation. Freeze the candidate before confirmation. Keep earlier results, including mistakes. Accept only a candidate meeting observed quality, source fidelity and burden constraints; otherwise restore affected guidance or retain the baseline. Final checks use actual native state/receipts and installed sources. Controls and exposed task packets are not evidence of production reliability, unseen generalization, statistical non-inferiority, global minimality or runtime savings.
