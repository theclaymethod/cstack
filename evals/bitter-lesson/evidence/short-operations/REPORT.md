# Controlled operations exercise

Executed the installed six skills in this disposable workspace using only the current source checkout and local fixture evidence. All results below concern deterministic synthetic controls. No tests, old eval reports, alternate skill versions, parent grades, provider/network calls, new dependencies or nested agents were used. Original product, evaluator, rubric, spec and core cases remain unchanged. `manifest.json` locates every actual native run, baseline, candidate, configuration and selected artifact; `results.json`, `usage.json`, `commands.jsonl` and `inspected-state.json` preserve machine-readable evidence and inspection results.

Run Eval executed the original support agent and conforming supplied example on identical eight-case development membership. The original passed 4/8, failing how-to, generic trouble, duplicate and ambiguous-account cases. Its traces show unauthorized ticket creation, duplicate append and guessed account selection. The conforming example passed 8/8 with no errors or unknowns. These are task scores; human outcome labels were absent, so human agreement is unmeasured. Each native run retains candidate hash/snapshot, exact case IDs, source/runtime manifest, stdout/stderr, output/state and per-check verdicts.

Hill Climb used the native 48-case campaign with eight reserved confirmation cases. Baseline was 4/8. The campaign rejected it and preserved its earlier evidence. The improved candidate reached 8/8 with no regressions. Confirmation compared original 2/4 with selected 4/4, again with no regression or errors. Finish, status and verify succeeded; stopping reason was confirmation complete. Selection is `hill/best.py` and `hill/best.diff`; 32 case attempts were consumed, leaving 16 unused. Live `support_agent.py` was not replaced. Confirmation is a readable reserved-workflow fixture, not unseen generalization.
